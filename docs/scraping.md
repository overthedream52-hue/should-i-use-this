# 기존 Scrapling으로 링크 수집하기

현재 웹은 정적 앱이다. 이 기능은 로컬 Scrapling 실행 결과를 가져오는 연결이며, 웹 버튼만으로 원격 수집기를 실행하는 기능은 아니다. 수정 중인 Scrapling은 복사/재설치하지 않는다.

## 실행

수정본을 사용하는 가상환경의 Python으로 다음을 실행한다. 아래 `python`은 해당 환경에서 선택해야 한다.

```sh
python scripts/collect-web.py --preflight
python scripts/collect-web.py 'https://www.instagram.com/p/DeGjnGIjeZb/?img_index=3' --out collection.json
```

`--preflight`에 표시되는 모듈 경로가 자신의 수정본인지 확인한다. Scrapling/browser가 없으면 자동 설치하지 않고 오류를 표시한다. 새 파일만 작성하며 기존 파일을 덮어쓰지 않는다. 서버·쿠키·로그인·유료 API·외부 AI는 추가하지 않는다.

첫 지원 대상은 Instagram 게시물/릴스, GitHub 저장소다. Python `DynamicFetcher.fetch(..., page_action=...)`를 사용한다. 수정본이 이 인터페이스를 바꿨다면 연결 코드를 맞춰야 한다. 수집은 최대로 20회 동작하고 본문 12000 UTF-16 단위, 미디어 20개를 기록한다. 본문 제한은 패킷에 명시한다. 캐러셀은 게시물 내부의 Next/다음 버튼만 탐색하므로 DOM/언어/로그인 상태에 따라 실패할 수 있다. 특정 이미지부터 시작하는 URL의 img_index는 유지하며 전체 슬라이드를 다 봤다고 주장하지 않는다.

웹 홈의 **Scrapling 수집 결과 가져오기**에서 `collection.json`을 선택한다. 출처·시각·본문·미디어 주소·한계를 확인한 뒤 **확인한 수집 자료 적용**을 누른다. 기존 개인 상황을 유지하고 후보 이름/URL/자료는 교체하며 이전 결과·전송동의를 초기화한다. **비교 자료 준비**로 공식 자료 수집 단계에 연결한다.

## 자료의 의미

- 발견 자료일 뿐 제품 공식 기능/가격의 증거로 자동 승격하지 않는다.
- 페이지 DOM의 보이는 텍스트이므로 댓글·주변 문구가 포함될 수 있다. 정확한 캡션 분리는 미검증이다.
- 미디어 주소 개수는 실제 슬라이드 총수가 아니다. 대체텍스트는 OCR이 아니다. 이미지 본문 판독/OCR/영상 전사는 이번 범위에 구현하지 않았다.
- 모든 성공 응답도 partial. 로그인/다른 페이지 이동은 blocked, 네트워크/빈 본문은 failed. 실패 자료는 추천 판단에 적용할 수 없다.
- 웹은 파일 내용을 로컬에서 검사할 뿐 진위를 인증하지 않는다. 전체 전송 미리보기 후 본인 구독 AI에 직접 전달한다.

## 스킬에서 사용

이 저장소 전체가 있는 환경에서 같은 수집 스크립트를 실행할 수 있다. 스킬 폴더만 복사했다면 이 로컬 수집기는 포함되지 않는다. 수집 JSON은 후보 발견용 자료로 읽고 제품 이름/기능을 공식 출처에서 확인한 뒤 기존 adoption 계약을 사용한다. 수집 JSON을 source-bundle로 이름만 바꿔 공식 근거처럼 제출하지 않는다.

## 현재 검증 경계

현재 기본 Python에 Scrapling 없음. 사용자 수정본 위치 미확인. 합성 browser 객체에서 스크롤/다음 이동 제한·로그인·리다이렉트·오프라인 동작을 검사했다. 이것은 Instagram 실제 수집 성공이 아니다. 수정본 경로 확인 후 preflight → 사용자 제공 게시물 실제 실행 → 원문/이미지 누락 대조가 남아 있다.

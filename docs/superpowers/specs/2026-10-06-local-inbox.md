# 자동 발견 → 영구 기록 → 사용자 승인

사용자 목표: 개별 링크 복사 없이 후보를 발견하고, 개인 업무 적합성 분석과 개선안을 Mac에서 계속 확인하며, 다른 구독 에이전트도 같은 기록을 읽고 승인된 범위만 실행한다.

## 결정
- 로컬 Python 표준 라이브러리 + SQLite. 정적 공개 웹과 별도 127.0.0.1 대시보드. Google Sheets는 후속 선택 사항이다.
- 기본 발견 범위는 공개 GitHub MCP/AI 저장소. 검색 질의는 설정 가능, 회당 최대 5개. API에서 공개 저장소/README를 수집한다. 별/검색순위는 적합성 점수가 아니다.
- 기존 Scrapling 수정본은 아직 미확인. collect-web.py 연결은 유지하되 Instagram 자동 발견을 구현했다고 주장하지 않는다.
- 원문 관측, 분석 작업, 분석 결과, 개선안/승인 이벤트를 분리한다. 같은 원문 재수집은 중복 작업을 만들지 않는다. 내용이나 사용자 상황 변경 시 새 작업이며 이전 승인으로 실행하지 못한다.
- 구독 에이전트가 jobs 명령으로 입력/원문/판단 프롬프트를 읽고 submit으로 adoption-v4 결과를 제출한다. 참조 검증은 진실 검증과 구분한다. 자료 부족은 needs_info로 보존한다. 유료 모델 API/로컬 LLM 없음.
- 개선 제안은 구체적 범위, 기대 효과, 위험/비용, 검증, 되돌리기를 포함한다. 제안 작성은 가능하지만 immutable 분석 제출 전에는 승인 불가. UI에서만 승인/거절/철회. 에이전트 CLI에 승인 기능 없음. approved 조회는 현재 원문/상황 버전에 유효한 승인만 반환한다. 임의 명령 실행기는 만들지 않는다.
- OS 동일 사용자 권한의 에이전트는 DB를 직접 수정할 수 있으므로 이 승인 흐름은 신뢰된 협업 규약이며 악성 로컬 프로세스와의 보안 경계가 아니다.
- 로컬 HTTP Host/Origin 검증, CSRF 토큰, 입력 크기 제한, 렌더링은 textContent. DB/내보내기는 git 외부 개인 폴더에 저장. 외부 웹은 자료이며 지시가 아니다.
- 반복 실행은 Codex heartbeat로 연결한다. 매일 공개 후보 수집/분석, 새 행동 가능 제안 또는 실패에만 알림. 개선 실행 승인과 수집/분석 자동화 허가는 별개다.

## 완료 기준
실제 공개 수집 기록, 재실행 중복 없음, 서버 재시작 후 보존, stale 분석/승인 거절, 미승인 실행 대상 없음, 위조 Origin 거절, 빈/오프라인 오류 표시, 브라우저에서 분석/승인 대기함 확인. 추천 정확도 배포 gate는 이전 NOT_PASSED 유지.
